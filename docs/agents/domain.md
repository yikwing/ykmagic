# Domain Docs: 单上下文

本仓库使用单上下文布局。

## 位置

- **CONTEXT.md** — 仓库根目录
- **ADRs** — `docs/adr/`

## CONTEXT.md

`CONTEXT.md` 包含项目的领域语言——核心概念、术语、边界和不变量。它回答：

- 这个系统做什么？
- 关键实体和它们的关系是什么？
- 什么业务规则是不可违反的？

技能 `improve-codebase-architecture`、`diagnose`、`tdd` 会读取它来学习项目的词汇表。

### 写入规则

- 用领域专家使用的语言写
- 定义会在代码中出现的术语（类名、函数名、模块名）
- 记录关键约束和不变量
- 当新的领域见解出现时更新它

## ADRs（架构决策记录）

`docs/adr/` 包含过去的架构决策——为什么选择这种方法而不是那种方法。每个 ADR 记录：

- **标题** — 简短的决策摘要
- **状态** — 已提议/已接受/已弃用/已取代
- **上下文** — 什么促使了这个决策
- **决策** — 我们选择了什么
- **后果** — 这个选择的影响

### 命名约定

```
docs/adr/NNNN-short-title.md
```

例如：`docs/adr/0001-use-koin-for-di.md`

### 何时写 ADR

- 架构模式选择（DI 框架、网络库、状态管理）
- 重大重构或迁移
- 技术栈变更
- 对未来开发有持久影响的任何决策

技能会在提出架构变更之前读取 ADRs，以避免重新引入已被拒绝的方法。
